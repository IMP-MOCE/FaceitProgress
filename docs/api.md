# Спецификация API

Машиночитаемая спецификация - [`openapi.json`](openapi.json) (OpenAPI 3.1). Она генерируется
из кода командой `python scripts/export_openapi.py`. Тест `test_published_openapi_matches_code`
падает, если файл расходится с реализацией. На запущенном сервисе интерактивная документация
открывается по адресу `http://localhost:8000/docs`.

Базовый путь: `/api/v1`. Формат данных: JSON. Время передаётся в ISO 8601 с часовым поясом (UTC).

## Аутентификация

1. `POST /auth/register` - регистрация по email и паролю (8–128 символов).
2. `POST /auth/login` - в ответе `access_token` (JWT, HS256) и `expires_in` (по умолчанию 1800 с).
3. Все остальные запросы, кроме `/health`, передают заголовок `Authorization: Bearer <token>`.

Токен содержит `sub` (id пользователя), `type=access`, `iat`, `exp`, `jti`. Сервер принимает
только алгоритм HS256 и обязательно проверяет `exp`. На каждом запросе он также проверяет,
что пользователь существует и активен: после удаления аккаунта токен перестаёт работать.

## Ресурсы

| Метод | Путь | Назначение | Успех | Ошибки |
|---|---|---|---|---|
| GET | `/health` | Доступность сервиса и БД | 200 | - |
| POST | `/auth/register` | Регистрация | 201 | 409, 422 |
| POST | `/auth/login` | Получение JWT | 200 | 401, 422, 429 |
| GET | `/users/me` | Текущий пользователь | 200 | 401 |
| DELETE | `/users/me` | Удаление аккаунта и всех данных | 204 | 401 |
| GET | `/players` | Отслеживаемые игроки (`limit`, `offset`) | 200 | 401 |
| POST | `/players` | Найти на FACEIT по нику или ссылке и загрузить историю | 201 + `Location` | 401, 404, 409, 422, 503 |
| GET | `/players/{id}` | Игрок | 200 | 401, 404 |
| PATCH | `/players/{id}` | Изменить заметку (`null` очищает) | 200 | 401, 404, 422 |
| DELETE | `/players/{id}` | Удалить игрока, его матчи и цели | 204 | 401, 404 |
| POST | `/players/{id}/sync` | Обновить профиль и историю из FACEIT | 200 | 401, 404, 503 |
| GET | `/players/{id}/matches` | История: `map`, `date_from`, `date_to`, `limit`, `offset` | 200 | 401, 404, 422 |
| GET | `/players/{id}/stats` | Обзор последних 20 матчей с теми же фильтрами | 200 | 401, 404, 422 |
| GET | `/goals` | Цели (`status`, `limit`, `offset`) | 200 | 401, 422 |
| POST | `/goals` | Поставить цель и сохранить снимок 20 матчей | 201 + `Location` | 401, 404, 409, 422 |
| GET | `/goals/{id}` | Цель с исходной выборкой | 200 | 401, 404 |
| PATCH | `/goals/{id}` | Изменить действие или закрыть цель (`completed`/`archived`) | 200 | 401, 404, 409, 422 |
| DELETE | `/goals/{id}` | Удалить цель со снимками | 204 | 401, 404 |
| GET | `/goals/{id}/progress` | Сравнить исходную выборку с первыми 20 матчами после цели | 200 | 401, 404 |

## Правила кодов ответа

| Код | Когда |
|---|---|
| 401 | Нет токена, токен истёк, подделан или пользователь удалён. Заголовок `WWW-Authenticate: Bearer` |
| 404 | Ресурс не существует **или принадлежит другому пользователю**: чужие данные неотличимы от несуществующих |
| 409 | Email занят; игрок уже добавлен; уже есть активная цель (в теле `active_goal_id`); закрытие неактивной цели |
| 422 | Ошибка валидации (`errors[]`), некорректная ссылка или ник, недостаточно данных для цели (`required`, `available`, `missing_match_ids`) |
| 429 | Больше 5 попыток входа в минуту для пары IP + email. Заголовок `Retry-After` |
| 503 | FACEIT недоступен. Сохранённые данные не меняются. Заголовок `Retry-After: 30` |

## Формат ошибки (RFC 9457)

```http
HTTP/1.1 409 Conflict
Content-Type: application/problem+json

{
  "type": "/problems/conflict",
  "title": "Конфликт с текущим состоянием",
  "status": 409,
  "detail": "У пользователя уже есть активная цель. Закройте её или передайте replace_active",
  "instance": "/api/v1/goals",
  "active_goal_id": 1
}
```

Ошибки валидации не возвращают введённые значения, чтобы пароль не попал в ответ или логи.
Непредвиденные ошибки возвращают 500 с общим текстом, а стек пишется только в лог сервера.

## Пример: обзор статистики

```http
GET /api/v1/players/1/stats?map=de_mirage
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

```json
{
  "player_id": 1,
  "formula_version": "1",
  "filters": {"map": "de_mirage", "date_from": null, "date_to": null},
  "matches_count": 20,
  "matches_available": 37,
  "period_from": "2026-09-29T09:00:00Z",
  "period_to": "2026-10-20T18:00:00Z",
  "win_rate": {"value": 55.0, "numerator": 11, "denominator": 20, "sample_size": 20, "note": null},
  "kd": {"value": 1.18, "numerator": 386, "denominator": 327, "sample_size": 20, "note": null},
  "synced_at": "2026-10-28T14:51:43.887807Z",
  "coverage": {"history_complete": false, "coverage_from": "2026-09-13T15:00:00Z"},
  "partial_coverage": false,
  "message": null
}
```

Реальный ответ сервиса для демо-профиля `demo_player`. `value` округлён до двух знаков. Числитель,
знаменатель и размер выборки возвращаются, чтобы результат можно было проверить вручную (S02).
Если под фильтр попало меньше 20 матчей, `message` сообщает, сколько их доступно.

## Статусы прогресса цели

| `status` | Значение |
|---|---|
| `collecting` | После постановки цели сыграно меньше 20 матчей в её контексте; `collected` показывает, сколько набрано |
| `incomplete_data` | В первых 20 матчах нет данных метрики (`missing_match_ids`); более поздние матчи не подставляются |
| `unrecoverable` | Начало периода вышло за загруженную историю - сравнение невозможно, цель можно заменить |
| `ready` | Новая выборка сохранена снимком; `change` в п.п. (`win_rate`) или числом (`kd`) |
