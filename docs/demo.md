# Демо-сценарий защиты

Показ идёт в веб-интерфейсе (http://localhost:8000/), проверки безопасности - в Swagger UI
(http://localhost:8000/docs). Все игроки вымышленные, данные встроенные демонстрационные
(`FACEIT_API_KEY` не задан). Общее время - 8–10 минут.

## Подготовка (до защиты)

```bash
docker compose up --build -d
```

```bash
docker compose exec api python -m app.seed_demo
```

Скрипт создаёт аккаунт `demo@example.com` (пароль указан в `app/seed_demo.py`) с игроком
`demo_player` и целью, «поставленной» 25 матчей назад. Цель помечена `[ДЕМО]`: это
подготовленный пример накопленных матчей, а не эффект тренировок (ПР1, раздел 11).

Откройте вкладки: интерфейс, Swagger UI, GitHub Actions с последним зелёным прогоном.
В инструментах разработчика браузера включите режим устройства 360 px - для показа адаптива.

## Часть 1. Конвейер (1 мин)

1. GitHub Actions → последний прогон: **Линтеры (backend, frontend) → Тесты и Сквозные тесты → Сборка образа**.
2. В сводке - таблица: число тестов и покрытие. Артефакты: `test-reports` (JUnit, coverage.xml)
   и `e2e-screenshots` (скриншоты интерфейса из сквозных тестов).

## Часть 2. Основной сценарий в интерфейсе (4 мин)

| Шаг | Действие | Что показать |
|---|---|---|
| 1 | Регистрация своего аккаунта | Вход сразу после регистрации; пароль короче 8 символов подсвечивается у поля |
| 2 | «Найти и добавить» с пустым полем | Подсказка, запрос не отправляется (S01) |
| 3 | `nobody_here`, затем `source_down` | «Игрок не найден» отличается от «Источник FACEIT временно недоступен» с кнопкой «Повторить» |
| 4 | Ссылка `https://www.faceit.com/ru/players/demo_player` | Профиль, ELO, время обновления, предупреждение о неполной истории (100 из 120 матчей) |
| 5 | Обзор | Доля побед и K/D с числителем, знаменателем и размером выборки; «Как считаются показатели» |
| 6 | Фильтр «de_mirage» → «Применить» | Показатели и история пересчитаны по одному набору матчей; пояс браузера указан |
| 7 | Вкладка «Сравнение 20/20» → «Все карты» | Две непересекающиеся группы, изменение в п.п. и абсолютное для K/D, словами и стрелкой |
| 8 | Вкладка «Карты» | Матчи по картам, пометка «меньше 10 матчей» |
| 9 | Вкладка «Сводка и рекомендации» | Наблюдение, ограничение, действие, «Показать матчи основания» |
| 10 | «Сделать целью» (или «Поставить цель») | Исходная точка показана до сохранения; после - страница цели «Сыграно 0 из 20» |
| 11 | Повторить постановку цели | Предложение явной замены текущей цели (S11, крит. 3) |
| 12 | Режим устройства 360 px | Карточки вместо таблицы, нет горизонтальной прокрутки |
| 13 | `patchy_player` → обзор | K/D по 18 матчам из 20: пропуск - не ноль |

## Часть 3. Безопасность (2–3 мин)

| Шаг | Действие | Ожидаемо |
|---|---|---|
| 1 | «Выйти» в интерфейсе → открыть `#/goals` | Возврат на вход. Тот же токен в Swagger получает 401: он отозван на сервере |
| 2 | Второй пользователь → **Authorize** в Swagger → `GET /goals/1`, `DELETE /players/1` | 404: чужие данные неотличимы от несуществующих (A01, IDOR) |
| 3 | Изменить один символ в токене → любой запрос | 401: подпись не сходится |
| 4 | 6 раз `POST /auth/login` с неверным паролем | Шестой - 429 с `Retry-After` (A07) |
| 5 | `POST /players` `{"query": "https://evil.example/players/x"}` | 422: ссылки только на faceit.com (A10) |
| 6 | Заголовки ответа `/` и `/api/v1/health` в инструментах разработчика | Разные CSP: `default-src 'self'` для интерфейса и `default-src 'none'` для API |

## Часть 4. Готовый прогресс цели (1 мин)

1. Войти как `demo@example.com` → «Цели» → цель `[ДЕМО]`.
2. «Было → Стало», изменение в процентных пунктах словами, оба состава матчей.
3. Обновить страницу - сравнение то же: снимок не меняется при обновлении истории.

## Вопросы, к которым стоит подготовиться

- **Почему 404, а не 403 для чужих данных?** 403 подтверждает, что ресурс существует, и позволяет
  перебирать id. 404 не раскрывает ничего.
- **Почему Argon2id?** Медленный по памяти и времени хеш, рекомендуется OWASP для паролей.
- **Как работает выход, если JWT без состояния?** `jti` токена записывается в `revoked_tokens` до
  момента `exp`; при каждом запросе проверяется одна строка по первичному ключу.
- **Где хранится токен в браузере и чем это опасно?** В `sessionStorage`. CSRF невозможен, риск XSS
  снижен строгой CSP, выводом только через `textContent` и коротким сроком жизни токена.
- **Почему правило срабатывает ровно на пороге 15 п.п.?** Так задано в каталоге ПР1; сравнение идёт
  в точных дробях, чтобы 60% → 45% не превратилось в 14,999… из-за плавающей точки.
- **Почему не сравниваются последние 20 игр, если первые после цели потеряны?** Это подмена выборки,
  и вывод о динамике стал бы неверным (ПР1, раздел 2.2). Сервис честно отвечает `unrecoverable`.
- **Как спецификация соответствует коду?** OpenAPI генерируется из кода. Тест сверяет опубликованный
  `docs/openapi.json` с приложением, а миграции - с моделями.
- **Как проверено, что интерфейс работает?** Сквозные тесты Playwright запускают настоящий сервер и
  браузер в CI на трёх ширинах экрана и падают при ошибке JS или нарушении CSP.
